## 판단

기능 개발은 여기서 끝내는 것을 권한다. 문제 정의, 결정론적 엔진, 사람의 승인 절차, 국내 AI 설명 검증, 합성 데이터 계보, 자동 검증과 공개 데모까지 연결한 프로젝트로서 포트폴리오에 남길 근거가 충분하다.

다만 모든 기능이 완전하거나 현장 적용이 검증된 제품이라고 표현해서는 안 된다. 이번 재검증에서 기존 자동 Gate는 모두 통과했지만, 추가 코드 추적과 재현으로 고객안내 문제와 보고서의 비교 기준 설명 오류를 확인했다. 종료는 이런 한계를 공개한 기술 데모의 보존을 의미한다. 아래 개선안은 구현하지 않았다.

## 이번 확인 범위와 한계

- Git 추적 파일 1,676개 전체 목록, 디렉터리 구성, 최근 변경 이력, main 및 v1.0.0 태그의 커밋을 확인했다. 원격 main·HEAD와 로컬 HEAD가 일치한다. 작업 시작 시 추적 파일 변경은 없었다.
- 핵심 승인 명세의 관련 절과 ADR, Safety 계산·개입·동의·계획 적용·설명 검증·운영 세션·PWA의 주요 경로를 테스트와 대조했다. src 110개, tests 76개, e2e 21개가 추적되어 있다.
- Word 7개와 PDF 8개에서 본문을 추출했다. 최종윤문본 Word, 최신 검토본 PDF, README를 중심으로 수치·구현·한계를 대조했다. 추출 목록은 `evidence/document-inventory.json`에 있다.
- PDF 검토본의 표지와 검증 결과 페이지를 렌더링해 확인했다. 최종 Word 재렌더링은 LibreOffice 실행 파일 부재로 실패했다. 따라서 Word 전체 페이지의 현재 레이아웃을 재검증했다고 주장하지 않는다.
- 공개 GitHub README·Releases 및 실제 데모의 관리자 화면을 브라우저에서 확인했다. 배포 화면의 전체 폐루프는 이번에 직접 조작하지 않았으며, 로컬 전체 E2E로 검증했다.
- 전체 파일을 한 줄씩 수동 정독한 완전 감사, 모든 문헌 원문의 재검증, 전체 영상 재생·재렌더링, 새 환경에서 clone/install한 검증, 외부 API·GPU 재실행, 실제 사용자 검증은 수행하지 않았다. 로컬 clean-start는 서버·브라우저 재기동 검증이다.

## 확인된 정정 및 개선 사항

### 1. 비교 실험의 설명을 바로잡는 것이 가장 중요하다

최종윤문본 Word의 3.3.1은 11/30 위반 결과를 ‘안전과 ETA의 가중합’ 방식의 결과로 설명한다. 실제 `src/evals/frozenBenchmark.ts:341`의 `BALANCED_ONLY`는 배송 건수의 최대–최소 차를 우선 최소화하고, 동률이면 ETA와 후보 ID를 비교한다. `docs/evals.md` 5절도 작업량 균형 기준으로 정의한다.

권장 문장: **동일한 30개 합성 변형에서 ETA 우선 방식은 17건, 배송 건수 균형 우선 방식은 11건의 실행 불가 후보를 선택했고, 안전 제약을 먼저 적용한 SafeRoute는 0건이었다.**

이 결과를 가중합 최적화 전반의 열등함, 실제 사고감소 또는 경쟁 제품 대비 우월성의 증거로 옮기지 않는다. 이전 윤문 기록의 숫자 보존은 비교 대상의 의미까지 검증했다는 뜻이 아니다.

### 2. 고객안내 초안에서 이관 배송지가 누락된다

`src/application/operations/createDecisionWorkspace.ts:865`와 `src/application/apply-plan/index.ts:153`은 원 기사의 `baselinePlanId`에 남아 있는 배송지만 고객안내 대상으로 고른다. 반면 이관 처리 `src/domain/interventions/engine.ts:621`은 이관 배송지의 plan ID를 수신 기사 것으로 바꾼다.

추가 재현에서 `demo-courier-009 → demo-courier-025` 4건 이관은 `APPLIED`가 되었지만, 이동한 `demo-stop-009-05`부터 `08`까지 4개 모두 안내 초안이 없었다. 원 기사에 남은 4개 배송지에 대해서만 초안이 생성되었다. 기존 테스트는 원 계획에 남은 배송지 수를 기대하므로 이 누락을 잡지 못한다.

개선한다면 선택 개입의 영향 배송지와 양쪽 계획의 변경 대상을 기준으로 안내를 생성해야 한다. 현재 상태에서는 ‘모든 영향 고객의 안내가 완결됐다’고 설명하지 않는다. 실제 메시지를 발송하는 기능은 없어 외부 발송 피해는 재현 범위에 없다.

### 3. 안내문 시각에 UTC가 그대로 들어간다

`src/application/apply-plan/index.ts:165`는 ISO 문자열에서 `slice(11, 16)`으로 시각을 자른다. 재현 입력 `2026-07-25T09:08:00.000Z`의 한국시간은 18:08이지만 안내문에는 09:08로 표시되었다. 저장된 `updatedEta` 값은 그대로이고 사람에게 보여주는 문장의 시각이 잘못된다.

개선한다면 승인된 IANA 시간대에 맞춰 표시해야 한다. 재현 결과와 실행 스크립트는 `evidence/customer-notice-probe.json`, `evidence/customer-notice-probe.mjs`에 보존했다. 스크립트는 저장소 루트에서 실행하며 외부 요청이나 실제 운영 데이터를 사용하지 않는다.

### 4. 이관 후 배송지별 일정 재구성은 제한되어 있다

`src/domain/interventions/engine.ts:608`의 이관은 소유 기사·plan ID·작업량·기사 종료시각·버전을 바꾸지만, 이 함수에서 각 배송지의 sequence, 개별 ETA 및 이동구간을 새로 재구성하지 않는다. 위 재현에서도 옮겨진 4개 배송지의 ETA는 모두 변경 전과 같았다.

따라서 ‘실제 도로와 인계를 고려한 이관 경로·배송지별 ETA 최적화가 완성됐다’는 주장은 피해야 한다. 기존 합성 구간을 재사용하는 계획 변경 시뮬레이션으로 설명하는 것이 정확하다. 이를 현실적인 경로 문제로 확대하는 작업은 현재 종료 목적에 비해 크므로 권하지 않는다.

### 5. 보고서의 시점과 기술 목록을 포트폴리오에서 구분한다

- 최종윤문본은 단위 449·E2E 58을 기재하고, PDF 검토본은 단위 462·과거 E2E 58, README는 462·70을 기재한다. 과거 제출본을 덮어쓸 필요는 없지만 포트폴리오에서는 날짜와 버전을 붙인 최신 결과를 사용한다.
- 최종윤문본의 Tailwind CSS·Lucide 활용 표시는 현재 앱의 package.json 및 CSS 구현과 맞지 않는다. 현재 공개 앱의 기술 설명은 React·TypeScript·Vite·CSS custom properties·Zod·Vitest·Playwright를 기준으로 한다.
- ‘GPS 미수집’이라는 포괄적인 문구에는 주의가 필요하다. `src/application/riderLiveLocation.ts`에는 사용자 요청 후 기기 위치를 메모리에서만 처리하는 기능이 있고 ADR-124에 경계가 기록되어 있다. 실제 기사 GPS의 서버 저장·공유·안전계산 연동을 하지 않는다는 설명과, 기기 위치 기능 자체가 없다는 설명을 구분한다.
- A100 ‘300시간’은 배정 시간인지 전체 사용량인지 명확히 구분해야 한다. v2 학습 요약의 `trainingSeconds`는 약 1,980초이며 이는 개별 실행 시간이다. 이 값만으로 전체 300시간 사용을 입증하거나 부정할 수 없다.
- 보고서의 향후 파일럿·현직 기사 인터뷰 계획은 대회 당시 계획으로 보존한다. 현재 포트폴리오에서는 ‘후속 실서비스 개발 계획 없음, 기술 데모로 종료’라는 방향을 별도로 밝히면 된다.

## 남길 가치가 큰 내용

1. 사고확률처럼 보일 수 있는 문제 정의를 계획 검증 문제로 바꾼 판단.
2. Safety Budget과 AI 설명 권한을 분리하고 실패 시 템플릿으로 돌아가는 구조.
3. 수신 기사까지 검사하고 양쪽 기사 응답·관리자 승인·재검증을 연결한 상태기계.
4. 결정론적 합성 데이터, 경계 테스트, 고정 평가와 해시로 결과를 추적한 과정.
5. A.X Local v1 7/12에서 v2 12/12로 개선했지만 지연·운영 준비 때문에 공개 실행에는 넣지 않은 판단. 이는 저장 증거를 대조한 결과이며 이번에 모델을 재학습·재평가한 것은 아니다.
6. 관리자 공간 이해도 실패를 숨기지 않고 기본 화면 승격을 보류한 기록. 기사 Round 2 성공과 현재 공개 제품 전체의 사용자 검증 완료는 서로 다르다.

## 종료 범위

현재 승인된 v1.0.0 코드·제출 보고서·영상은 이력으로 보존한다. 이번 검토는 새 기능, 안전 규칙 변경, 보고서 원문 수정, 커밋·푸시·배포, GitHub Archive 설정 변경을 수행하지 않았다. 검토 결과와 재검증 증거만 별도 폴더에 남겼다.

수용기준은 기존 검증의 실제 재실행, 발견사항과 미검증 범위 공개, 원본 보존이다. 모두 충족했다. 남은 결함은 수정 완료로 표시하지 않는다.

개선 우선순위는 **보고서의 비교 기준 정정 → 포트폴리오의 개인 기여·대표 산출물 안내 → 필요할 때만 고객안내 두 결함 수정**이다. 새 모델, 실제 TMS·인증·GPS 연동, 창업 계획, 큰 UI 리팩터링은 권하지 않는다.
