## 문서 상태

- 상태: Approved
- 담당: 김용우
- 최종 갱신: 2026-09-05
- 기준: 대회 제출 보존본 `v1.0.0` 이후 최종 점검과 보정
- 결정: ADR-183. 개인 포트폴리오 기술 데모로 종료하며 실서비스·창업으로 확대하지 않는다.

## 어떤 프로젝트로 남기는가

현재 남은 배송계획을 따라 운영상 안전여유가 언제 바닥나는지 예측하고, 개입이 다른 기사에게 위험을 전가하는지 검사한 뒤 사람의 동의와 승인으로 계획을 적용하는 기술 데모다. 핵심 성과는 기능 수가 아니라 **결정론적 계산, 제한된 AI 권한, 사람의 결정권, 적용·감사의 연결을 코드와 회귀 테스트로 구현한 것**이다.

대회에서는 결선에 진출하지 못했다. 이 결과와 별개로 설계·구현·학습·실험의 과정은 개인 포트폴리오에 남긴다. 실패한 사람 검토나 합성 데이터의 한계를 성공한 현장 검증처럼 설명하지 않는다.

## 이번에 수정한 결함

| 문제 | 수정 | 확인 방법 |
|---|---|---|
| 물량이관 후 출발 계획만 조회해 이관 배송지 고객안내가 누락됨 | 적용 계층에서 버전이 변경된 모든 계획의 미완료 배송지를 조회하고 배송지마다 하나의 안내 ID 생성 | 이관 배송지 8개를 포함한 단위 회귀, 실제 합성 운영 이관 사례의 누락 4곳 재확인 |
| UTC 문자열 일부를 한국 현지 시각처럼 표시함 | UTC ETA는 보존하고 담당 기사의 IANA 시간대로 날짜·시간·시간대 표시 | 한국 자정 경계와 미국 뉴욕 시간대 회귀 |
| 안내의 적용 버전이 출발 계획에 고정됨 | 배송지의 실제 소속 계획 버전을 기록하고 안내 기록 시 적용 ETA·버전 재확인 | 모든 대상의 ETA·버전 일치, 변조 ETA 거부 |

이관 누락 재현 사례는 `demo-courier-009 → demo-courier-025`, 배송지 `demo-stop-009-05`부터 `08`까지다. 수정 전에는 안내 4개에 이관 배송지가 전부 빠졌고, 수정 후에는 출발·수신 계획의 미완료 배송지 총 16개에 안내를 생성한다. `2026-07-25T09:08:00.000Z`는 `2026. 7. 25. 18:08 (Asia/Seoul)`로 표시한다.

초기화된 긴 결정 ID와 배송지 ID를 합치면 계약의 100자 한도를 넘는 회귀도 확인했다. 안내 ID는 별도 UUID로 생성하고 원래 결정·배송지 ID는 필드로 보존한다. 적용 재시도는 기존 안내를 재사용한다. 브라우저 코드 크기의 기존 한도는 변경하지 않았다.

고객안내는 계속 `PREVIEW_ONLY`, `actualDeliverySent=false`다. Safety Budget·임계치·Risk Transfer Guard·동의·승인 권한은 바꾸지 않았다.

## 대회 제출본을 읽을 때의 정정 사항

DOCX·PDF·영상·기존 태그는 제출 당시 기록으로 보존한다. 아래 내용은 현재 포트폴리오 설명의 기준이다.

| 항목 | 정정 또는 해석 |
|---|---|
| 최종 제안서 3.3.1의 “안전과 ETA의 가중합” 비교군 | 실제 `BALANCED_ONLY`는 배송 건수의 최대–최소 차이를 최소화한다. 동률은 ETA, 후보 ID 순서로 정한다. 이 비교군의 합성 하드 제약 위반이 11/30이다. 안전 가중합 모델과 비교해 우월성을 입증한 결과가 아니다. |
| 기술 스택의 Tailwind·Lucide 표기 | 현재 핵심 앱의 직접 의존성은 React·React DOM·Zod이며 스타일은 CSS로 구현했다. TypeScript·Vite·Vitest·Playwright가 개발·검증 도구다. |
| 보고서별 테스트 수 차이 | DOCX의 449/58, PDF 검토본의 462/58은 작성 당시 수치다. 이번 마감 검증 수치는 별도 날짜와 증거로 제시한다. |
| GPS 미연결이라는 포괄적 표현 | 사용자가 켜는 기기 위치 표시는 구현되어 있다. 해당 위치는 기기 메모리에서만 사용하며 서버·관리자·Safety 계산에 전달하지 않는다. 실제 배송 위치 추적 서비스가 아니다. |
| A100 300시간 | 배정량·계획량과 실제 누적 사용량을 구분할 근거가 부족해 개인 성과 수치로 사용하지 않는다. 학습 실행별 로그·설정·결과를 근거로 설명한다. |
| 현장 파일럿·사업화 계획 | 당시 제안서의 미래 계획이다. 현재 프로젝트의 확정 후속 작업으로 간주하지 않는다. |

비교군의 정의는 [동결 비교 구현](../src/evals/frozenBenchmark.ts)과 [평가 계획](./evals.md)이 근거다. 현재 설명은 [기술 보고서](./technical-report.md)에 통합했다.

## 마감 검증

수정 전에는 기존 전체 Gate가 통과했지만 고객안내 결함을 발견했다. 해당 결함을 재현하는 테스트 3개가 기존 코드에서 실패하는 것을 확인한 뒤 수정했고, 완료 배송지 제외·빈 대상 롤백·변조 ETA 거부도 확인했다. 테스트 통과가 미발견 결함의 부재를 보장하지 않는다는 점을 남긴다.

최종 실행 결과는 [최종 Gate](../artifacts/evals/final-readiness-latest.json), [단위·계약 테스트](../artifacts/evals/unit-summary.json), [종합 판정](../artifacts/evals/goal-completion-latest.json)에 기록한다. 수정 전 점검 기록과 증거는 [최종 검토](../output/portfolio/2026-09-05/review.md)에 보존한다. 이 기록에서 지적한 고객안내 결함은 이 문서의 수정 내역으로 대체된다.

2026-09-05 최종 Gate는 **6개 명령·17개 점검, 단위·계약 467/467, E2E 70/70, clean start 3/3, 합성 전략 비교 90회**로 통과했다. Risk Transfer 경계 23/23, 결정 상태기계 경계 30/30도 유지했다. 2.5D 추가 gzip 예산은 기존 50 KiB 한도 안에서 통과했다.

[첫 전체 실행의 실패 기록](../output/portfolio/2026-09-05/closure-evidence/first-gate-failed.json)도 보존한다. 초기화 ID 길이·번들 크기 회귀와 완료 배송지 테스트 fixture의 잔여 물량 불일치를 수정한 후 위 최종 Gate를 다시 실행했다. [이관 안내 수정 후 재현 결과](../output/portfolio/2026-09-05/closure-evidence/customer-notice-probe-after.json)는 수정 전 증거와 별도로 보존했다.

이번에 새로 실행하지 않은 것은 외부 AI Live 호출, GPU 재학습, 실제 사람 검토다. 기존 학습·사람 검토 결과는 날짜가 있는 과거 증거로만 인용한다.

## 종료 시 남긴 한계

1. **물량이관의 일정 재계산:** 소속·작업량·계획 버전·예상 종료시각은 갱신하지만 이관 배송지의 개별 ETA·순서·도로 구간을 새로 최적화하지 않는다. 안내 초안은 합성 계획에 저장된 ETA를 사용한다. 실제 도로에서 실현 가능한 이관 계획을 검증한 것은 아니다.
2. **현장 일반화:** 임계치와 가중치는 사고 라벨로 보정하지 않았다. 합성 비교 0건 위반은 실제 사고 감소 효과가 아니다.
3. **관리자 이해도:** 공간 이해도 Round 3은 3명·0/6 trial·중대 오인 6건이었다. 후속 Round 4와 합성 운영 서비스 역할별 독립 검토는 수행하지 않았다. 기본 화면은 2D로 유지한다.
4. **실서비스 경계:** 실제 인증·권한·TMS 쓰기·고객 메시지 전송은 구현 범위 밖이다. 공개 데모와 로컬 재현 자료를 남긴다.

가장 의미 있는 추가 발전은 실제 이관 일정의 일관성 검증과 관리자 이해도 재검토였을 것이다. 다만 현재 목적은 기술 포트폴리오이므로 이번 마감에 포함하지 않는다. 이를 위해 신규 인프라나 서비스를 추가하지 않는다.

## 포트폴리오용 설명

> SafeRoute AI의 기획부터 설계·개발·모델 학습·검증·발표까지 전 과정을 수행했습니다. 남은 배송계획의 안전한계 초과 시점을 계산하고, 물량이관이 다른 기사에게 위험을 전가하지 않는지 검사한 뒤 기사 동의와 관리자 승인으로 합성 계획을 적용하는 폐루프를 구현했습니다. AI에는 문서·설명 역할만 부여하고 안전 수치와 실행 가능성은 결정론적 코드가 소유하도록 분리했습니다. 합성 비교 실험과 자동화 테스트를 구축했으며, 관리자 이해도 검토 실패와 이관 일정 재계산의 한계를 함께 공개한 기술 데모로 마무리했습니다.

## 수용기준·비목표·미결사항

- 수용기준: 고객안내 누락·시간대 회귀 해결, 기존 최종 Gate 통과, 제출 원본 보존, 설명과 코드의 비교군 정의 일치, 본인 기여 및 미검증 한계 명시.
- 비목표: 기능 확대, 신규 인증·전송·유료 API, 실제 데이터 수집, 경로 최적화 확장, 사업화·현장 파일럿.
- 미결사항: 마감을 막는 제품 결정 없음. 위 한계는 미완료 약속이 아니라 공개된 종료 범위다.
