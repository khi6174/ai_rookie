## 문서 상태

- 상태: Draft
- 담당: 팀 안전빵

- 점검 기준: 본선 MVP와 본선 이후 파일럿 준비를 포함한 궁극적 목표
- 기준 문서: `AGENTS.md`, `docs/product-spec.md`, `docs/evals.md`, `docs/demo-script.md`

## 1. 결론

SafeRoute의 결정론적 P0 폐루프는 작동한다. Safety Budget과 Time-to-Breach, Risk Transfer Guard, 두 기사 동의, 관리자 승인, 최신 계획 재검증, 원자적 계획·ETA 적용과 감사기록을 같은 결정 ID로 재현했다. 기상청 부분 Live는 Demo와 섞지 않는 명시적 Weather Fallback으로 차단했고, 국내 AI 출력은 수치·추천을 소유하지 않는 Gate 뒤에 두었다.

현재 판정은 다음과 같다.

| 관점 | 잠정 진척도 | 판정 |
|---|---:|---|
| AI ROOKIE 본선 MVP 준비 | 82% | 조건부 진행 가능 |
| 본선 이후 파일럿까지 포함한 궁극적 목표 | 63% | 제품 논리는 확보, 현장 검증은 미착수 |

진척도는 공식 심사점수가 아니다. 제품 단계 종료조건, 실행 증거, 문서 상태, 실제 데이터·사용자 검증과 릴리스 재현성을 함께 반영한 내부 추정치다.

## 2. 간단 데모 리허설 결과

2026-07-17에 `pnpm run test:e2e:clean-start`를 실행했다.

- 새 Vite 서버와 독립 브라우저로 핵심 폐루프 3회 실행
- 3/3 통과
- 총 14.12초
- 두 기사 동의 → 관리자 승인 → 계획·ETA·고객안내 적용 통과

이는 기능 리허설이다. 발표자의 실제 한국어 대사 속도, 역할 분담, 복구 신호와 녹화 상태를 검증한 인간 발표 리허설로 간주하지 않는다.

## 3. 궁극적 목표 단계별 점검

| 단계 | 현재 상태 | 근거 | 남은 조건 |
|---|---|---|---|
| 1. 결정론적 기반 | 완료 | 대표 fixture 3개, 계약·단조성·정확값 테스트 | 없음 |
| 2. 안전한 개입 | 완료 | 다섯 단일 개입, 허용 묶음 6종, 8건 허용·12건 차단 | 화면에서 다섯 유형을 모두 보여줄지는 데모 범위 결정 필요 |
| 3. 인간 중심 폐루프 | 거의 완료 | 같은 결정 ID, 두 기사 동의, 승인 잠금, 재검증, 원자 적용, reset E2E | 사용자 과업 관찰과 실제 운영 권한 검토 |
| 4. 국내 AI 근거 계층 | 상당 부분 완료 | Upstage 11/12+안전 Fallback, K-EXAONE 12/12, A.X 오프라인 28/30+Fallback | A.X API 비교, 공급자 보존·쿼터 확인, 반복 실행 |
| 5. 본선 증명 | 조건부 | Vitest 164/164, Playwright 9/9, 네 해상도, clean start 3회 | 증거 산출물 누락 해소, Draft 문서 정리, 인간 발표 리허설 |
| 6. 파일럿 준비 | 미착수 | 개인정보·AI 정책과 데이터 계약은 존재 | 실제 운영 입력, 현장 승인, 사용자 연구, TMS·지도 연동, 운영 모니터링 |

## 4. 국내 트랙 6개 심사기준 중간판정

| 심사기준 | 중간판정 | 확보한 증거 | 가장 큰 약점 |
|---|---|---|---|
| 창의성 | 강함 | 현재 점수 대신 52분 후·17번째 배송지의 미래 계획 초과를 예측 | 기존 솔루션과의 정량 비교표가 아직 약함 |
| 혁신성 | 강함 | 안전 하드 제약, Risk Transfer Guard, 설명과 결정권 분리 | 실제 운영 데이터에서의 일반화는 검증하지 않음 |
| 추진성 | 조건부 강함 | 작동 상태기계, 164개 테스트, E2E·A100·API 실행 증거 | 현재 변경 대부분이 미커밋이라 릴리스 재현성이 낮음 |
| 성장성 | 강함 | Upstage·K-EXAONE·A.X를 같은 안전 계약과 Fallback으로 비교 | A.X API 미실행, 모델 역할의 장기 운영 근거 부족 |
| 실효성 | 조건부 | 계획·순서·물량·ETA·고객안내가 실제 Demo store에 원자 적용 | 기사·관리자 사용자 과업, TMS·지도, 현장 KPI가 없음 |
| 가치성 | 강함 | 비징벌성, 기사 통제권, 위험전가 차단, 개인정보 최소화, 감사기록 | 실제 현장의 수용성·형평성 효과는 아직 주장할 수 없음 |

## 5. 통과한 핵심 Gate

### 5.1 제품·안전

- 불안전한 12건 이관을 ETA 이점과 무관하게 차단한다.
- 두 기사 동의 전 관리자 승인을 잠근다.
- 승인 직전 최신 계획을 재검증한다.
- 적용 실패 시 기존 계획을 유지하는 원자적 경계를 둔다.
- LLM 문구가 Safety Budget, 실행 가능성 또는 추천을 바꾸지 못한다.

### 5.2 데이터·AI

- KMA 부분 Live의 준비 필드를 Demo 결측값과 섞지 않는다.
- 현재 시간당 적설과 미래 120분 시정을 명시적 차단 필드로 남긴다.
- 모든 활성 날씨 계산 입력은 `MOCK`, `isDemo=true`다.
- 실제 생성 결과의 검증 실패는 화면 승인 없이 Fallback으로 전환한다.
- API 키, 비밀번호, SSH 접속정보와 원문 응답을 평가 산출물에 저장하지 않는다.

### 5.3 검증

- Vitest: 14개 파일, 164/164
- Playwright: 9/9
- 프로덕션 빌드: 통과
- 관리자 1440×900·1280×720, 기사 390×844·360×800: 가로 넘침 없음
- 기사 터치 대상: 최소 44px
- 인앱 브라우저 콘솔 경고·오류: 0건
- clean start 핵심 폐루프: 3/3, 14.12초

## 6. 발견한 위험과 누락

### P0 — 다음 릴리스 체크포인트 전에 해결

1. **미커밋 작업**: 현재 구현·문서·평가 산출물의 상당 부분이 작업 트리에만 있다. 검증된 상태를 잃거나 팀원이 같은 결과를 재현하지 못할 위험이 가장 크다.
2. **평가 산출물 목록 불일치 — 해결(2026-07-17)**: `pnpm run test:e2e`와 `pnpm run eval:core-artifacts`로 다음 8개 파일의 최신본과 SHA-256 불변 run을 생성했다. 대표 fixture·개입·이관 경계는 현재 도메인 코드에서 재계산하고, 국내 AI·Upstage는 기존 비식별 smoke 결과를 집계한다.
   - `run-manifest.json`
   - `unit-summary.json`
   - `scenario-results.csv`
   - `baseline-comparison.csv`
   - `risk-transfer-boundaries.csv`
   - `domestic-ai-smoke.csv`
   - `upstage-roundtrip.csv`
   - `accessibility-summary.json`
3. **Draft 운영 문서**: `docs/demo-script.md`, `docs/evals.md`, `docs/design-system.md`, `docs/data-sources.md`, `docs/gpu-benchmark-runbook.md`가 Draft다. 구현 증거와 문서 수용기준을 대조한 뒤 승인 또는 명시적 보류가 필요하다.

### P1 — 본선 증명 전 해결 권장

1. 리허설 체크리스트 19개가 아직 인간 확인으로 서명되지 않았다. 자동 테스트가 증명하는 항목과 발표자·보조자가 직접 확인할 항목을 분리해야 한다.
2. 본편 UI는 대표 안전 후보에 집중하고 있어 다섯 단일 개입 유형을 모두 한 장면에서 보여주지 않는다. 본편에 넣지 않는다면 Q&A 증거 화면을 확정해야 한다.
3. A.X API 키 발급 후 공통 12과업 비교가 남았다. 키가 없더라도 A.X 오프라인 기준선과 안전 Fallback은 유지할 수 있다.
4. 현재 날씨 Live Gate에는 현재 시간당 적설과 미래 120분 시정이 남았다. 승인된 출처·정책이 없으면 Weather Fallback을 유지해야 한다.

### P2 — 본선 이후 파일럿 단계

1. 기사·관리자 대상 과업 성공률, 이해도, 의사결정 시간과 거절 수용성 평가
2. 실제 TMS·지도·권한·보존·감사 시스템 연동
3. 운영 장애 모니터링, 롤백, 접근통제와 데이터 삭제 절차
4. 실제 사고감소가 아닌 운영 가능성부터 검증하는 제한된 파일럿

## 7. 다음 작업 우선순위

1. 현재 검증 상태를 코드·문서·평가 산출물 단위로 검토한 뒤 체크포인트 커밋과 원격 푸시를 만든다.
2. 자동 검증 가능한 리허설 항목과 팀원이 직접 확인해야 할 항목을 분리하고 `docs/demo-script.md`·`docs/evals.md`의 승인 조건을 정리한다.
3. **완료(2026-07-17)**: Fastest-only·Balanced-only·SafeRoute를 30개 frozen 변형의 같은 후보 집합에서 90회 비교했다. 하드 제약 위반은 Fastest 17건, Balanced 11건, SafeRoute 0건이며 합성 시뮬레이션 한계를 함께 기록했다.
4. **완료(2026-07-17)**: Risk Transfer Guard 직접 경계 20건과 4·8·12건 전체 계획 3건을 모두 통과했다. 다음은 시간·동의·버전 충돌 세트와 리허설 증거를 우선하고, A.X API가 준비되면 동일 12과업만 실행한다.

## 8. 결정사항

- P0 결정론적 폐루프는 계속 기준 구현으로 유지한다.
- KMA 전체 계약이 완성되기 전까지 Weather Fallback을 유지하며 필드 단위 Live·Demo 병합을 금지한다.
- Near-miss, 실제 TMS와 장식성 VARCO 연동은 현재 P0 완료 주장에 포함하지 않는다.
- 실제 사고감소, 현장 안전효과 또는 모델 fine-tuning 완료를 주장하지 않는다.

## 9. 미결사항

- Draft 문서별 승인 담당자와 승인 시점
- 다섯 단일 개입을 본편 또는 Q&A 중 어디에서 보여줄지
- A.X API 키 발급 시점과 반복 실행 예산
- 파일럿 대상 운영사·기사·관리자의 참여 가능 여부

## 10. 수용기준

- 중간점검의 모든 수치는 현재 저장소 파일 또는 이번 세션 실행 결과로 추적 가능하다.
- 구현 완료와 실제 현장 효과를 구분한다.
- 누락·Draft·미커밋 상태를 숨기지 않는다.
- 다음 우선순위가 P0 재현성과 궁극적 목표에 직접 연결된다.

## 11. 비목표

- 중간점검만으로 본선 제출 준비 완료를 선언하지 않는다.
- 실제 사용자 연구나 현장 파일럿을 수행한 것으로 간주하지 않는다.
- 새로운 안전 임계치, 개인정보 범위 또는 AI 권한을 확정하지 않는다.
- 이번 점검에서 Near-miss, TMS, 지도 또는 신규 모델 연동을 구현하지 않는다.
