## 1. 목적

이 문서는 SafeRoute AI의 차별점을 기능 목록이 아니라 하나의 검증 가능한 폐루프로 시연하기 위한 화면, 클릭, 대사, 시간과 복구 절차를 정의한다.

시연의 핵심 문장은 다음과 같다.

> 기존 시스템이 더 빠른 길을 찾는다면, SafeRoute는 현재 계획을 계속 수행해도 기사별 안전 가능영역 안에 있는지 먼저 묻고, 안전한 대안만 사람의 동의와 승인으로 적용합니다.

## 0. 2026-08-14 제출용 우승 컷

이 절은 제출 영상 본편의 권위 스크립트다. 아래의 기존 상세 타임라인은 기술 리허설과 질의응답 증거로 보존하되, 본편에서 모든 기능을 순서대로 소개하지 않는다.

### 0.1 본편이 남길 한 문장

> SafeRoute는 더 빠른 배송을 추천하기 전에, 현재 계획이 언제 안전한계를 넘는지 예측하고, 누구에게도 위험을 넘기지 않는 대안만 기사 동의와 관리자 승인으로 적용합니다.

### 0.2 본편 편집 원칙

- 한 명의 지원받는 기사와 한 명의 배송을 나눠 맡는 기사, 하나의 decision ID만 따라간다.
- 관리자 첫 장면은 여러 탭이 아니라 지도와 연결된 결정 카드가 함께 보이는 한 페이지다.
- 기능 이름보다 `52분`, `17번째`, `12건 차단`, `10분 휴식 + 8건 이관`, `두 기사 동의`, `계획 적용`을 먼저 말한다.
- 24명 Demo movement, Demo 2.5D, 전체 감사표, 공공 API와 모델 비교는 본편에서 설명하지 않는다.
- 국내 AI와 300개 이상 자동 검증은 마지막 20초의 신뢰 근거로만 사용한다.
- 합성·Demo·Simulation 표시를 숨기지 않으며 실제 사고감소 효과를 주장하지 않는다.

## 2. 시연에서 증명할 것

1. 현재 점수가 아니라 미래의 초과 시각과 배송지를 예측한다.
2. 위험 원인, 신뢰도와 결측을 숨기지 않는다.
3. 휴식·이관·순서·안전경로·Safe Delay를 같은 기준으로 비교한다.
4. 다른 기사에게 위험을 넘기는 12건 이관을 차단한다.
5. 기사와 관리자가 같은 결정 근거를 확인한다.
6. 동의와 승인 후에만 경로·순서·ETA가 함께 갱신된다.
7. Upstage는 근거 있는 설명만 만들며 숫자와 추천을 바꾸지 않는다.
8. 전후 안전·지연·형평성과 감사기록을 남긴다.

### 2.1 선택형 G5-A 20초 보조 시연

시간이 허용되면 관리자 지도에서 활성 decision을 선택하고 `경사 근거 자세히 보기 · Demo 2.5D`를 연다. `Demo 2.5D`, `Live 0명`, `세로 1.5배 · 합성 고도`를 먼저 읽은 뒤 현재→휴식→휴식 뒤 경사 노출→17번째 배송지 전 지원 순서를 짚는다. 오른쪽 구조화 수치에서 52분·29.9→47.2·10분 휴식·8건 이관과 같은 decision ID를 확인하고 키보드로 `2D로 돌아가기`를 실행한다.

대사: “이 화면은 실제 지형이나 3D 지도 주장이 아니라, 같은 결정의 합성 경사 맥락을 설명하는 선택형 Demo입니다. 높이 자체가 위험점수는 아니며, 2D와 같은 경로점과 Safety 결과를 사용합니다.”

이 보조 시연은 기사 동의→관리자 승인 폐루프를 대체하지 않는다. 시간이 부족하면 생략하고 질의응답에서만 보여준다.

### 3.1 수치 잠금 규칙

`52분`, `17번째 배송지`, `12건 차단`, `8건 가능`은 대표 시나리오의 필수 의미적 기대값이다. 현재·최소·개입 후 Budget, ETA 증가, 기여도 비율과 고객 도착시각은 엔진 회귀 테스트 통과 후 fixture manifest에서 읽는다.

스크립트에 수치를 손으로 중복 입력하지 않는다. 화면, 대사 카드와 결과표는 동일한 manifest를 사용한다. 정확값이 잠기기 전에는 임의의 `90→64` 같은 값을 발표하지 않는다.

| `관리자 / 지원받는 기사 / 배송을 나눠 맡는 기사` | 같은 decision의 역할 화면 전환 |
| `운행 / 안전지원 / 내 정보` | 기사 모바일 웹의 세 정보영역 전환 |
| `Demo 초기화` | 전체 fixture reset과 새 결정 ID 생성 |
| `Demo 이동 재생 / 일시정지 / 다음 5초 / 처음으로` | 24명 합성 위치의 30초 단기 이벤트를 재현하며 Live 위치로 사용하지 않음 |
| `오류 모사` | 적용 후 AI 설명을 결정론적 Fallback으로 전환 |

제출 본편은 `/stage`의 한 페이지 Stage Mode를 사용한다. 아직 구현되지 않은 발표자 단축키는 사용하지 않으며, 모든 상태 전이는 화면에 보이는 버튼으로만 진행한다. 기존 루트 화면과 `/operations`는 기술 리허설·질의응답·운영 서비스 보조 증거로 유지한다.

- A100 로컬 기준선과 중복·커버리지 분석 전후
- Upstage 문서 왕복 strict JSON·인용·숫자 일치율
- 사용량·지연·비용·실패와 fallback 로그

“국내 AI를 많이 사용했다”가 아니라 어떤 역할에서 어떤 기준선보다 나았고 무엇을 제품에 채택했는지 설명한다. VARCO는 대회 가이드상 후속 에셋 API이며, P0에 필요하지 않은 장식성 연동을 하지 않았다고 명시한다.

## 7. Fallback 스크립트

### 7.1 Upstage timeout 또는 malformed

- 화면: `설명 서비스 지연 · 결정 결과는 유지됩니다`와 `Fallback template`
- 대사: “설명 API가 응답하지 않아 검증된 템플릿으로 전환했습니다. Safety Budget과 추천은 처음부터 결정론 엔진이 소유하므로 계획은 바뀌지 않습니다.”
- 확인: 같은 결정 ID, Budget, 추천, ETA 유지

### 7.2 날씨·지도 Live 실패

- 화면: `Demo fixture · Weather Fallback`, `INCOMPLETE_COVERAGE`, 현재 시간당 적설·미래 120분 시정 차단
- 대사: “기상청 Live 표본은 일부 필드가 검증됐지만 전체 날씨 계약을 충족하지 못했습니다. Live와 Demo를 필드별로 섞지 않고 고정 Demo 타임라인 전체로 전환했습니다.”
- 확인: `liveEvidenceUsedForSafety=false`, `fallbackTimelineUsedForSafety=true`, `mixedLiveAndDemoFields=false`

### 7.3 안전한 후보 없음

- 화면: `안전한 후보 없음`, Safe Delay·물량감축 요청
- 대사: “안전 제약을 만족하는 후보가 없으면 억지로 최선안을 추천하지 않고 계획 축소나 지연을 요청합니다.”

### 7.4 적용 실패

- 화면: `APPLY_FAILED`, 기존 경로와 ETA 유지
- 대사: “적용 중 오류가 발생해 기존 확정 계획을 유지했습니다. 부분 적용을 성공처럼 표시하지 않습니다.”

### 7.5 발표 클릭 오류

- `→`로 다음 유효 단계 진행
- 상태 전이가 막히면 오류를 숨기지 않고 `R`로 reset 후 30초 축약 경로 사용
- reset은 새 결정 ID를 만들고 이전 데모 상태를 제거한다.

| 실효성 | 경로·순서·ETA·고객안내 갱신 | E2E와 사용자 과업 결과 |
| 가치성 | 형평성·비징벌성·감사기록 | 안전·지연·이해도·개인정보 지표 |

### 10.1 기존 제품과의 차이를 묻는 Q&A

| 비교 대상 | 강점으로 인정하는 부분 | SafeRoute의 차별점 | 시연에서 보여줄 증거 |
|---|---|---|---|
| 아틀란 트럭 | 기사에게 익숙한 지도·경로·배송 진행 경험 | 실제 내비게이션을 대체하지 않고, 안전한 후보만 동의·승인 뒤 계획에 적용 | 현재→휴식→지원 기준의 compact route와 적용 전후 배송순서·ETA |
| KBS 모빌리티 AI 영상·Riderlog 계열 | 운전행동과 안전 이벤트를 예방적 피드백으로 전환 | 사고감지·점수에서 멈추지 않고 남은 업무계획의 Time-to-Breach와 실행 가능한 개입을 계산 | 52분·17번째 배송지 예측, 원인·신뢰도, 다섯 개입 비교 |
| SafeRoute AI | 두 레퍼런스의 현장 맥락을 연결 | Risk Transfer Guard, 기사 동의·관리자 승인, 원자적 계획 적용과 감사 | 12건 이관 차단→8건 이관 합의→경로·ETA·고객안내 갱신 |

발표 문구는 `두 제품을 합쳤다`가 아니라 다음 문장으로 고정한다.

> 아틀란 트럭이 기사의 운행 수행 경험을, 모빌리티 AI가 예방적 안전 신호를 보여준다면, SafeRoute는 그 맥락에서 누구에게 어떤 지원을 언제 적용할지 사람과 합의해 실제 계획을 바꾸는 운영 의사결정 계층입니다.

## 11. 수용기준

- 본편은 180초 안에 하나의 결정 ID로 끝난다.
- 모든 표시 수치는 고정 fixture와 도메인 출력에서 읽는다.
- 12건 이관 차단과 8건 조건부 가능이 재현된다.
- 기사·수신 기사 동의와 관리자 승인 없이는 계획이 바뀌지 않는다.
- Upstage 실패 상태에서도 수치·추천을 유지하고 폐루프를 끝낸다.
- 적용 성공·실패와 Live·Demo 상태가 시각적으로 구분된다.
- clean start 3회 연속 통과 후에만 문서를 Approved로 바꾼다.

## 12. 비목표

- 모든 제품 화면을 시연
- 실제 고객 메시지 발송
- 실제 지도 내비게이션과 TMS 연동

- Near-miss가 P0 폐루프를 지연시키는 경우 본편에 강제 포함

### 12.1 제출 마감 검증 공백 고지

발표 시작 또는 Q&A에서 다음 문장을 사용한다.

> 기술 폐루프와 기사 제품 경계 평가는 통과했지만, 관리자 공간 화면의 마지막 독립 이해도 평가는 제출 일정상 수행하지 못했습니다. 따라서 관리자 이해도와 현장 사용성이 검증 완료됐다고 주장하지 않습니다.

Round 3 `DO_NOT_PROMOTE` 결과는 삭제하지 않으며, G5-B Round 4 미실시를 자동 테스트나 팀 내부 판단으로 대체하지 않는다.
