# SafeRoute AI 3분 시연 스크립트

## 문서 상태

- 상태: Draft
- 담당: 팀 안전빵
- 최종 갱신: 2026-07-17
- 승인 조건: 고정 fixture 정확값 테스트와 clean start 3회 연속 시연 통과

## 1. 목적

이 문서는 SafeRoute AI의 차별점을 기능 목록이 아니라 하나의 검증 가능한 폐루프로 시연하기 위한 화면, 클릭, 대사, 시간과 복구 절차를 정의한다.

시연의 핵심 문장은 다음과 같다.

> 기존 시스템이 더 빠른 길을 찾는다면, SafeRoute는 현재 계획을 계속 수행해도 기사별 안전 가능영역 안에 있는지 먼저 묻고, 안전한 대안만 사람의 동의와 승인으로 적용합니다.

## 2. 시연에서 증명할 것

1. 현재 점수가 아니라 미래의 초과 시각과 배송지를 예측한다.
2. 위험 원인, 신뢰도와 결측을 숨기지 않는다.
3. 휴식·이관·순서·안전경로·Safe Delay를 같은 기준으로 비교한다.
4. 다른 기사에게 위험을 넘기는 12건 이관을 차단한다.
5. 기사와 관리자가 같은 결정 근거를 확인한다.
6. 동의와 승인 후에만 경로·순서·ETA가 함께 갱신된다.
7. Upstage는 근거 있는 설명만 만들며 숫자와 추천을 바꾸지 않는다.
8. 전후 안전·지연·형평성과 감사기록을 남긴다.

## 3. 고정 시나리오

- fixture ID: `scenario-rain-hill-longshift-v1`
- 데이터 모드: `DEMO / mock` — 실제 공공데이터 연결 전 합성 fixture
- 권역: 관악구를 모사한 합성 언덕·골목·빌라 권역
- 누적 근무: 9.4시간
- 환경: 강수 증가, 경사·골목·계단 노출
- 기준 예측: 52분 후 17번째 남은 배송지에서 Budget 30 미만 예상
- 비교 장면: 휴식, 8건·12건 이관, 순서변경, 안전경로, Safe Delay, 묶음
- 필수 판정: 12건 이관 차단, 8건 이관은 모든 하드 제약과 양측 동의 충족 시 가능

### 3.1 수치 잠금 규칙

`52분`, `17번째 배송지`, `12건 차단`, `8건 가능`은 대표 시나리오의 필수 의미적 기대값이다. 현재·최소·개입 후 Budget, ETA 증가, 기여도 비율과 고객 도착시각은 엔진 회귀 테스트 통과 후 fixture manifest에서 읽는다.

스크립트에 수치를 손으로 중복 입력하지 않는다. 화면, 대사 카드와 결과표는 동일한 manifest를 사용한다. 정확값이 잠기기 전에는 임의의 `90→64` 같은 값을 발표하지 않는다.

## 4. 사전 준비

### 4.1 환경

- 1280×720 Stage Mode
- 브라우저 확대 100%
- 알림·자동 업데이트·불필요한 탭 비활성화
- 새 프로필 또는 저장 상태 초기화
- API 키 있음/없음 두 상태 사전 점검
- 네트워크 실패 강제 전환 준비

### 4.2 시작 상태

- `Reset demo` 실행
- 결정 ID가 새로 생성됨
- 데이터 모드 배지가 `Demo fixture · Weather Fallback`으로 보임
- 기준 계획 외 승인·동의·고객안내·감사 이벤트 없음
- 관리자 Control Tower와 기사 화면이 동일한 결정 ID를 조회

### 4.3 발표자 단축키

| 키 | 행동 |
|---|---|
| `→` | 다음 데모 단계 |
| `←` | 이전 설명 단계만 이동, 도메인 상태는 되돌리지 않음 |
| `R` | 확인 모달 후 전체 fixture reset |
| `F` | Live 오류를 모사하고 Demo fallback 전환 |
| `S` | Stage Mode 전환 |

단축키는 실제 버튼과 같은 상태 전이 명령을 사용한다. 화면만 바꾸는 별도 연출 상태를 만들지 않는다.

## 6. 국내 AI 트랙 보조 장면

3분 본편을 방해하지 않도록 질문 응답 또는 보고서 부록에서 다음을 보여준다.

- A.X·K-EXAONE 공통 텍스트 smoke benchmark 결과표와 VARCO P0 보류 근거
- 모델·프롬프트·seed·거절 사유가 있는 생성 manifest
- A100 로컬 기준선과 중복·커버리지 분석 전후
- Upstage 문서 왕복 strict JSON·인용·숫자 일치율
- 사용량·지연·비용·실패와 fallback 로그

“국내 AI를 많이 사용했다”가 아니라 어떤 역할에서 어떤 기준선보다 나았고 무엇을 제품에 채택했는지 설명한다. VARCO는 대회 가이드상 후속 에셋 API이며, P0에 필요하지 않은 장식성 연동을 하지 않았다고 명시한다.

## 7. Fallback 스크립트

### 7.1 Upstage timeout 또는 malformed

- 화면: `설명 서비스 지연 · 결정 결과는 유지됩니다`와 `Fallback template`
- 대사: “설명 API가 응답하지 않아 검증된 템플릿으로 전환했습니다. Safety Budget과 추천은 처음부터 결정론 엔진이 소유하므로 계획은 바뀌지 않습니다.”
- 확인: 같은 결정 ID, Budget, 추천, ETA 유지

### 7.2 날씨·지도 Live 실패

- 화면: `Demo fixture · Weather Fallback`, `INCOMPLETE_COVERAGE`, 현재 시간당 적설·미래 120분 시정 차단
- 대사: “기상청 Live 표본은 일부 필드가 검증됐지만 전체 날씨 계약을 충족하지 못했습니다. Live와 Demo를 필드별로 섞지 않고 고정 Demo 타임라인 전체로 전환했습니다.”
- 확인: `liveEvidenceUsedForSafety=false`, `fallbackTimelineUsedForSafety=true`, `mixedLiveAndDemoFields=false`

### 7.3 안전한 후보 없음

- 화면: `안전한 후보 없음`, Safe Delay·물량감축 요청
- 대사: “안전 제약을 만족하는 후보가 없으면 억지로 최선안을 추천하지 않고 계획 축소나 지연을 요청합니다.”

### 7.4 적용 실패

- 화면: `APPLY_FAILED`, 기존 경로와 ETA 유지
- 대사: “적용 중 오류가 발생해 기존 확정 계획을 유지했습니다. 부분 적용을 성공처럼 표시하지 않습니다.”

### 7.5 발표 클릭 오류

- `→`로 다음 유효 단계 진행
- 상태 전이가 막히면 오류를 숨기지 않고 `R`로 reset 후 30초 축약 경로 사용
- reset은 새 결정 ID를 만들고 이전 데모 상태를 제거한다.

## 8. 30초 축약 경로

1. 52분 후 17번째 배송지 초과 표시
2. 12건 이관 차단 사유 표시
3. 사전 동의가 기록된 데모 스냅샷 로드
4. 관리자 승인과 원자적 계획 적용
5. 전후 지표·감사기록 표시

축약 스냅샷은 `Demo pre-consented`를 명시하고 정상 3분 흐름의 실행 증거로 사용하지 않는다.

## 11. 수용기준

- 본편은 180초 안에 하나의 결정 ID로 끝난다.
- 모든 표시 수치는 고정 fixture와 도메인 출력에서 읽는다.
- 12건 이관 차단과 8건 조건부 가능이 재현된다.
- 기사·수신 기사 동의와 관리자 승인 없이는 계획이 바뀌지 않는다.
- Upstage 실패 상태에서도 수치·추천을 유지하고 폐루프를 끝낸다.
- 적용 성공·실패와 Live·Demo 상태가 시각적으로 구분된다.
- clean start 3회 연속 통과 후에만 문서를 Approved로 바꾼다.
