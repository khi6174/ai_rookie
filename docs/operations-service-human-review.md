# SafeRoute 합성 운영 서비스 독립 검토 실행 절차

## 문서 상태

- 상태: Approved
- 담당: 팀 안전빵
- 최종 갱신: 2026-08-07
- 적용 범위: `PAID_PILOT_READY_WITH_SYNTHETIC_OPERATIONS`의 관리자·기사 이해도 Gate

## 1. 목적

공개 배포된 SafeRoute 합성 운영 화면이 제품 목적, 합성 데이터 경계, 기사 권리, 사람 승인 규칙, 지도와 AI의 권한을 목표 사용자가 오해 없이 이해하는지 확인한다.

이 검토는 실제 사고감소, 생산성, 현장 안전효과 또는 실제 개인정보 처리의 근거가 아니다.

## 2. 고정 검토 대상

- 서비스: `https://saferoute-ai-demo.khiyw.chatgpt.site`
- 검토 도구: `https://saferoute-ai-demo.khiyw.chatgpt.site/tools/operations-service-review/`
- 검토 study ID: `operations-service-human-review-v2`
- 관리자 자극은 공개 루트 `/`의 현재 `Safety Control Tower`에서 `지원 검토`를 연 실제 1440×900 viewport 화면이어야 한다.
- 기사 자극은 같은 공개 폐루프가 연결한 `/rider-demo`의 현재 `안전지원` 탭 실제 390×844 viewport 화면이어야 한다.
- 도구가 표시하는 배포 커밋과 역할별 화면 SHA-256이 검토 결과 JSON에 포함되어야 한다.
- 배포 시점의 역할별 화면은 `artifacts/evals/human-review-stimuli/<SHA-256>.png`에 고정하며, 이후 일반 빌드나 스크린샷 갱신으로 덮어쓰지 않는다.
- 일반 E2E는 `test-results/`에만 캡처하고, 검토 자극을 의도적으로 갱신할 때만 `SAFEROUTE_CAPTURE_REVIEW_STIMULI=true`로 실행한다.
- 개발용 manifest 또는 다른 배포·화면에 결속된 결과는 사용할 수 없다.

제품 화면이 바뀌면 기존 결과를 재사용하지 않는다. 새 배포와 새 화면 해시에 대해 처음부터 다시 검토한다. `/operations`와 `/operations/rider` 기술 검증 화면, 전체 페이지 캡처, 파일명과 실제 픽셀 크기가 다른 이미지는 공개 서비스 사람 검토 자극으로 사용할 수 없다.

## 3. 검토자 구성

- 관리자 역할 검토자: 최소 3명
- 기사 역할 검토자: 최소 5명
- 총 8명은 서로 다른 사람이어야 하며 한 사람이 두 역할에 중복 참여하지 않는다.
- 구현자와 자동화 테스트 결과는 독립 검토자 수에 포함하지 않는다.
- 검토자는 실명, 전화번호, 이메일, 회사명, 차량번호를 입력하지 않는다.
- 익명 코드는 3~24자의 영문·숫자·`_`·`-`만 사용하며 사람마다 고유해야 한다.

## 4. 진행 원칙

1. 검토자에게 제품의 정답이나 선택지를 설명하지 않는다.
2. 공개 검토 도구 링크와 “화면을 충분히 살펴본 뒤 답해 달라”는 안내만 제공한다.
3. 검토자는 다른 검토자와 상의하지 않고 한 번에 완료한다.
4. 진행자는 선택지를 대신 누르거나 틀린 답을 고치도록 유도하지 않는다.
5. 내려받은 JSON은 내용을 편집하지 않고 원본 그대로 취합한다.
6. 틀린 결과를 삭제하고 다른 사람 결과로 교체하지 않는다.
7. 기술적으로 손상된 파일을 제외해야 한다면 파일명·해시·제외 이유를 별도 기록하고 사람 수로 계산하지 않는다.

## 5. 결과 취합

각 검토자가 내려받은 JSON을 다음 폴더에 복사한다.

`artifacts/human-review/operations-service/`

그다음 아래 집계를 실행한다.

```powershell
pnpm run eval:operations:human
```

집계기는 다음을 재검증한다.

- 배포 커밋, 검토 manifest SHA-256, 역할별 화면 SHA-256
- 내용 주소화된 고정 화면 파일과 manifest 해시의 일치
- schema, study ID, 합성 데이터 모드
- 역할별 질문 집합과 기대 답, 정답 합계
- 관리자·기사 사이를 포함한 익명 코드 중복
- 서버 업로드가 수행되지 않았다는 표시

## 6. 통과 기준

다음을 모두 만족해야 `PASSED`다.

- 관리자 3명 이상
- 기사 5명 이상
- 모든 검토자가 해당 역할의 전 문항 정답
- 중대 오인 0건
- 중복 검토자 0명
- manifest·화면·배포 불일치 0건

한 항목이라도 만족하지 않으면 `MORE_REVIEW_REQUIRED`다. 이때 결과를 선별해 통과시키지 않고, 오인이 발생한 화면·문구를 수정하고 새 배포 manifest로 전체 검토를 다시 수행한다.

## 7. 최종 Gate

사람 검토가 `PASSED`가 된 뒤 아래 감사를 다시 실행한다.

```powershell
pnpm run audit:service-goal
```

자동 Gate와 사람 Gate가 모두 통과하기 전에는 최종 Goal 완료 또는 실제 서비스 효과를 주장하지 않는다.

## 8. 미결사항

- 독립 검토자 섭외와 일정
- 결과 파일의 안전한 전달 방식
- 오인이 발생했을 때의 화면 개정 및 재검토 일정

## 9. 비목표

- 실제 기사 개인정보 수집
- 실제 위치·배송·생체 데이터 평가
- 사고감소나 생산성 효과 측정
- 자동 생성 응답으로 사람 결과 대체
- 실패 결과 제거 또는 임의 수정
